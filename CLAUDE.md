## Project overview

This is a Unity project (Editor version `6000.0.71f1`, Unity 6) built on the High Definition Render
Pipeline (HDRP, `com.unity.render-pipelines.high-definition` 17.0.4), started from Unity's "HDRP Empty
Template". It's a digital-twin visualization of an indoor/outdoor space ("LFBA"): a single main scene
(`Assets/OutdoorsScene.unity`) containing imported furniture/architecture models, materials, and lighting,
navigable in first-person via a custom camera controller with a runtime UI for toggling groups of lights.

There is no CI, build script, package.json, or test suite in this repo — it is a pure Unity Editor project.
All "building" and "running" happens inside the Unity Editor (Play mode) or via Unity's own Build pipeline
(File > Build Profiles), not from the command line.

## Working with this repo

- **Source of truth for game logic**: `Assets/Scripts/*.cs`. Currently two custom MonoBehaviours:
  - `CameraMove.cs` — first-person fly camera. Movement is locked to a fixed Y height (`fixedHeight`,
    default 1.65) so the camera simulates walking rather than flying; WASD/arrows move, Shift speeds up,
    holding the right mouse button enables mouselook (pitch/yaw only, no roll).
  - `LightController.cs` — builds an entirely runtime/code-driven UI (no prefabs, no UGUI assets) for
    toggling up to 8 light "groups" on/off. Each slot in the `lightObjects` array can be a single light or
    a parent GameObject whose children's `Light` components are collected via
    `GetComponentsInChildren<Light>(includeInactive: true)`. Press `L` in Play mode to show/hide the panel.
    All UI (Canvas, panel, rows, toggles, buttons) is constructed procedurally in `BuildUI()` — if you need
    to change the panel's look, edit the `Color*`/layout constants and the `CreateRect`/`AddImage`/`AddText`
    helpers at the bottom of the file rather than looking for a `.prefab`.
  - Code comments and Inspector labels in this codebase are written in Japanese; match that convention when
    editing these scripts.
- **Scenes**: `Assets/OutdoorsScene.unity` is the only scene. Its associated Global Volume Profile (sky/fog/
  post-processing) lives at `Assets/OutdoorsScene/Global Volume Profile.asset`.
- **Materials**: `Assets/Materials/` — many are imported/renamed with non-ASCII (Japanese) filenames; these
  are legitimate assets, not encoding errors.
- **HDRP config**: `Assets/Settings/HDRPDefaultResources/` holds the pipeline asset and global settings;
  `Assets/Settings/HDRP {Balanced,Performant,High Fidelity}.asset` are the quality-tier volume profiles.
  There's also a stray root-level `Assets/HDRPDefaultResources/` — check which one a given scene/quality
  level actually references before assuming edits to one affect rendering.
- **Git LFS**: binary asset types (`.fbx`, `.png`, `.jpg/.jpeg`, `.psd`, `.tga`, `.tif/.tiff`, `.exr`, `.hdr`,
  `.asset`) are tracked via LFS (see `.gitattributes`). Note `.asset` files (materials, volume profiles,
  render pipeline settings, the Readme) are LFS-tracked YAML — treat them as binary for diffing purposes
  even though `git show` may render them as text.
- **Do not hand-edit** `Library/`, `Temp/`, `Logs/`, or `UserSettings/` — these are regenerated by the Unity
  Editor and are not meaningful to modify directly (and are typically gitignored).
- **`.meta` files**: every asset has a paired `.meta` file holding its GUID and import settings. If you
  add/rename/delete an asset file, the matching `.meta` file must be added/renamed/deleted alongside it, or
  Unity will regenerate a new GUID and break every reference to that asset (materials, scene object links,
  Inspector-assigned fields like `LightController`'s `lightObjects` array).
